# Chapter 1: You Can't Even Exit Vim

*"The first failure: I couldn't exit Vim. The last failure: I built an entire operating system so I'd never be locked out again."*

---

## The Beginning

It started with a simple programming assignment. Open a file in Vim, edit it, save it, exit. Except I couldn't figure out how to exit.

`:q` didn't work because I had unsaved changes.  
`:wq` didn't work because I was in insert mode.  
`Ctrl+C` just beeped at me.

I was trapped in a text editor. A *text editor*. And that's when I realized: **if I don't understand the system, the system owns me.**

---

## From Vim to Sovereignty

That moment in Vim was the first domino. If I didn't control the editor, I didn't control the code. If I didn't control the code, I didn't control the compiler. If I didn't control the compiler, I didn't control the operating system. If I didn't control the operating system, I was a tenant in someone else's world.

So I decided to build my own world.

Not because I hated Vim (I learned to love it).  
Not because I was some genius prodigy (I failed constantly).  
But because **being locked out is unacceptable**.

---

## The Pattern

This pattern—**not understanding → being controlled → refusing to accept it → learning/building**—became the heartbeat of everything that followed.

- Can't exit Vim → Learn modal editing → Build my own editor bindings
- Can't understand ZyBooks → Reverse-engineer compiler → Build FlameLang
- Can't find 7% nonprofits → Hardcode it into PBC operating agreement
- Can't trust corporate AI → Build sovereign AI architecture
- Can't save my sister → Build entire medical simulation framework

Every failure became fuel. Every lock-out became a blueprint for sovereignty.
