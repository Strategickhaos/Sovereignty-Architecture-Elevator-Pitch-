## Contradiction

Antibody classification was being made on surface error string alone —
not on the payload contents. A Statsig useGateValue failure and a
token-in-URL event both produce console errors, but one is LOW/benign
and the other is CRITICAL/security. Classifying on surface causes
CRITICAL events to be silently dropped as noise.


**Invariant violated:** `INV-003` — Classification must depend on payload, not surface error alone

## Understanding

The missing law: every antibody rule needs a two-stage gate —
(1) surface pattern match, then (2) payload field inspection.
If payload contains access_token / id_token / phone_number → escalate regardless
of which surface pattern triggered.

## Invention

**Payload-Aware Antibody Router**

A two-stage classifier:
  Stage 1: surface pattern match (existing antibody trigger patterns)
  Stage 2: payload field scan (access_token, id_token, phone_number, otp)
If Stage 2 hits → override to CRITICAL regardless of Stage 1 severity.
