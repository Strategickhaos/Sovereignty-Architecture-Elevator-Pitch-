## Key Concepts

### Agents as State

Agents are not tasks. They are **state in the organism**. Each agent represents a collapsed possibility in quantum computation space. Every "review requested" = **uncollapsed branch** awaiting measurement.

### Agent Lifecycle States

- **PROPOSED**: Agent concept proposed but not yet implemented
- **DEVELOPING**: Agent under active development
- **TESTING**: Agent in testing/validation phase
- **ACTIVE**: Agent deployed and operational
- **EVOLVED**: Agent superseded by evolved version
- **DEPRECATED**: Agent retired or replaced

### Relational Graph

Agents are connected through:
- **deps**: Dependencies within same track
- **upstream_deps**: Dependencies on agents from other tracks
- **supersedes**: Agent replaces or evolves from another agent
- **conflicts**: Mutually exclusive agents
- **synergies**: Agents that amplify each other

## Usage

### For Developers

1. **Add a new agent**: Edit the appropriate track YAML file
2. **Define relationships**: Use `dependencies` and `upstream_deps`
3. **Specify outputs**: Document what the agent produces
4. **Link issues**: Add GitHub issue numbers to `github_issues` array

### For Discord Bot

The bot reads `agents/index.yml` for routing rules and track assignments.

The Technical Documentation Engine auto-generates docs from these YAML files.
